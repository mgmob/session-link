# Контракт: handoff v2, линии работы и хранилище

**Статус:** нормативный документ. Здесь — **что именно** реализовать. Рассуждения, отвергнутые
варианты и обоснования живут в отдельной спеке-обсуждении; сюда попадает только принятое.

Правила чтения: **обязан / должен** — требование, проверяемое тестом из §10; **можно** — свобода
реализации; «сейчас» — описание текущего поведения `v0.1.0`, от которого считается дельта.

---

## 1. Принцип, из которого следует остальное

**Персистентна линия работы, эфемерна сессия.**

Долгоживущая сущность — поток работы (`unit`); сессия — попытка его продвинуть, и она умирает.
Преемник восстанавливается **из записи**, а не воскрешением предка: возможность спросить предка
(`askCommand`) — удобство и справка, а не механизм непрерывности.

Отсюда две границы, которые реализация **не** должна переходить:

- не строить поверх этого «адресуемые возобновляемые сессии» как основу непрерывности;
- не превращать session-link в оркестратор: **кого и когда запускать — решает план работ и человек
  (или control-plane), а не инструмент и не агент**. `askCommand` — справка, а не пульт.

## 2. Хранилище (`store`)

### 2.1. Расположение

Базовый путь — `.pi/session_link`. Корень выбирается так:

1. если `cwd` принадлежит git-репозиторию → `store = <git-common-dir>/.pi/session_link`,
   где `git-common-dir` = вывод `git rev-parse --git-common-dir` (абсолютизированный);
2. иначе → `store = <cwd>/.pi/session_link` (как сейчас).

Причина правила 1: git **уже** держит common-dir общим для всех worktree одного клона, поэтому линии,
ведущиеся из разных рабочих деревьев одного репозитория, видят друг друга без сети, демона и
дополнительного кода.

**Плата, которую надо знать.** Содержимое `git-common-dir` не версионируется и не уезжает по
`push`/`pull`: store общий для дерева, но локальный для клона. Реализация **не должна** класть в
store ничего, потеря чего непереживаема, и **не должна** считать `.git` надёжным долговременным
хранилищем.

### 2.2. Раскладка

```
<store>/
  index.json                     оглавление линий (§4)
  .lock                          файл-маркер блокировки (§5)
  handoff.json                   безымянная линия — голова
  handoff.md                     её же человекочитаемая проекция
  handoff-<stamp>.json           её архивы
  <unit>/handoff.json            названная линия — голова
  <unit>/handoff.md
  <unit>/handoff-<stamp>.json    архивы линии
```

`<stamp>` — как сейчас: `createdAt` с заменой `:` и `.` на `-`.

### 2.3. Поиск головы линии

Сигнатура — `findHandoff(cwd, unit?)` (сейчас `findHandoff(cwd)`). Порядок:

1. `unit` задан → `<store>/<unit>/handoff.json`;
2. `unit` не задан → `<store>/handoff.json`;
3. **legacy-путь** `<cwd>/.pi/session_link/handoff.json` — там, где store лежал до правила §2.1;
4. ничего.

### 2.4. Две миграции — ортогональны, не путать

**По месту:** `<cwd>/.pi/session_link` → `<git-common-dir>/.pi/session_link`. Выполняется
**при первой записи** в git-репозитории; отложить нельзя — иначе линия раздваивается (старый файл в
рабочем дереве, новый в общем store). Переносится голова и её архивы **этой** папки.

**По имени:** плоский слот → `<store>/<unit>/`. Выполняется командой `/session-link-name <unit>` с
именем, которое дал оператор. Не происходит само.

В обоих случаях `parentHandoffPath` — абсолютный путь, поэтому цепочка переживает перенос головы.
Архивы **чужих** линий не двигаются никогда.

**Столкновение при переносе по месту.** Безымянный слот в общем store **один**, а legacy-store мог
остаться в нескольких worktree. Если слот занят другой цепочкой (иные `sessionId` и
`parentHandoffPath`), сливать молча **запрещено**: это развилка, обрабатывается по §6. Тихая
перезапись потеряла бы чужую историю, а склейка двух цепочек солгала бы о происхождении.

## 3. `unit` — имя линии

### 3.1. Формат

Регулярное выражение: `^[a-z0-9][a-z0-9-]{0,63}$`.

Проверка **строгая, без молчаливой нормализации**: имя, не прошедшее проверку, отвергается с
подсказкой. Sluggify разрешён **только** как генератор подсказки в тексте отказа, никогда как
источник истины.

Дополнительно запрещены имена, зарезервированные Windows (без учёта регистра и расширения):
`con`, `prn`, `aux`, `nul`, `com1`–`com9`, `lpt1`–`lpt9` — каталог с таким именем на Windows не
создаётся.

Только нижний регистр — не косметика: FS Windows регистронезависима, Linux — нет; иначе `Foo` и
`foo` окажутся одной линией на одной ОС и двумя на другой.

### 3.2. Безымянная линия

Отсутствие `unit` — **легальное состояние**, не ошибка. В store есть один безымянный слот, лежащий
плоско (§2.2); он же — место, где живут все файлы схемы v1.

Правило вывода: `unit` задаётся аргументом при первом handoff линии, далее **наследуется** из
handoff'а, на который указывает `parentHandoffPath`. Если родителя нет и аргумент не задан —
писать в безымянный слот. **Выводить `unit` из имени папки запрещено**: линии переезжают между
папками, и имя папки врёт именно там, где миграция нужна.

### 3.3. Совпадение имени — не всегда коллизия

Раз store привязан к репозиторию/папке, две разные папки столкнуться не могут. Внутри одного store
случаи различаются **по данным**:

| Условие | Это | Действие |
| --- | --- | --- |
| `unit` в индексе, `parentHandoffPath` = `head` | продолжение линии | обычная запись, вопросов нет |
| `unit` в индексе, `parentHandoffPath` ≠ `head` | развилка | §6 |
| запись индекса указывает на другой `cwd` | переезд (или ошибка) | спросить «линия переехала сюда?» |

Автоподбор суффикса (`-2`) для нового имени запрещён.

### 3.4. Режим `auto`

`auto` идёт без паузы на диалог, спросить там некого. Поэтому:

- нет родителя и нет `unit` → писать в безымянную линию. **Отказ запрещён:** `writeHandoff`
  вызывается до фазы авторства, и отказ означал бы сессию вообще без handoff'а;
- сработала развилка → производную линию завести автоматически, пометив в handoff и в логе, что
  оператор её не подтверждал.

В `manual` оба вопроса задаются в фазе ревью.

## 4. Оглавление `index.json`

```jsonc
{
  "schema": "session-link/index/v1",
  "units": {
    "<unit>": {
      "head": "<unit>/handoff.json",         // путь относительно store
      "updatedAt": "2026-08-05T11:40:00.000Z",
      "sessions": 4,
      "state": "active",                     // active | done | abandoned
      "cwd": "/abs/path/where/the/line/works"
    }
  }
}
```

**Состояние линии.** Линия — цель, сессия — попытка. **Провал сессии не проваливает линию:**
неудачная сессия оставляет обычное звено с честной записью (`blockers` / `deliberatelySkipped`), а
`state` остаётся `active`. В `done`/`abandoned` линию переводит только явное действие.

**`index.json` — производный кэш, не источник истины.** Всё его содержимое восстановимо обходом
`<store>/*/handoff.json`. Обязательна команда пересборки (`--rebuild-index`); пересборка должна
давать тот же результат, что и штатное обновление. Безымянная линия в оглавление **не попадает** —
её незачем искать по имени.

## 5. Транзакция и блокировка

**Гранулярность — весь store.** Файл-маркер `.lock` в корне store. `index.json` один на store, точка
конкуренции общая, per-unit гранулярность её не спасает.

**Под локом находятся все пути записи**, а не только основной. Их сейчас два:

1. запись handoff'а (`writeHandoff`) — пишет `handoff.json`, `handoff.md` и копирует архив;
2. отметка о принятии handoff'а преемником (`markCommitted`) — read-modify-write по живому файлу,
   выполняемый **после** старта дочерней сессии, то есть ровно тогда, когда живых сессий две.

Порядок внутри лока: `read index.json` → проверка развилки (§6) → архивация → запись
`<unit>/handoff.{json,md}` через temp + `rename` → обновление `index.json` через temp + `rename` →
release. **Данные первыми, индекс последним:** устаревший индекс чинится пересборкой, потерянный
handoff — нет.

Проигравший гонку за лок получает **внятный отказ**, а не тихую перезапись.

**Протухший лок.** Требуются: таймаут ожидания; признак живости владельца (pid + время старта
процесса, а не одно лишь наличие файла); перехват протухшего лока с записью в лог. Без этого первое
же падение процесса делает запись handoff'а в проекте невозможной навсегда — цена выше цены гонки,
которую лок предотвращает.

## 6. Развилки

Определение без эвристик:

> handoff, у которого `parentHandoffPath` ≠ текущему `head` линии, — развилка.

При срабатывании: не перезаписывать молча, а завести **производную линию** (`<unit>-b2`, `<unit>-b3`,
… — следующий свободный суффикс). Имя предлагает инструмент, **подтверждает оператор**; занятое имя —
отказ, а не молчаливое переиспользование. В `auto` подтверждения нет — заводить автоматически с
пометкой (§3.4). Оператор в любом случае должен быть предупреждён о ветвлении.

## 7. Схема handoff v2

### 7.1. Три зоны вместо двух

Сейчас документ разделён на **конверт** (владелец — код: `sessionRef`, `askCommand`, `driver`,
`cwd`, времена) и **тело** (владелец — агент). Тело расщепляется надвое:

| Зона | Владелец | Содержание |
| --- | --- | --- |
| конверт | код | как обратиться к предку, идентификаторы, времена — как сейчас |
| **выводимая часть** | **код** | факты: изменённые файлы и ветка из `git`, результаты прогонов, длительность, `seq` |
| авторская часть | агент | смысл: `goal`, `summary`, `nextStep`, `decisions`, `blockers` |

Правило: **факты собираются, смысл пишется.** Агент выводимую часть не пишет и не правит — факт
можно прокомментировать, но не переписать. Инструмент, в свою очередь, не пытается вывести смысл:
«что сделано» из диффа не следует, «почему так решили» — тем более.

Следствие, ради которого это делается: сессия, умершая **до** фазы авторства, оставляет не пустоту,
а факты. Пометка «DRAFT» в проекции уже существует — теперь у черновика есть содержимое.

### 7.2. Дельта к v1

Строка схемы: `session-link/handoff/v2`.

Добавляются:

| Поле | Тип | Зона | Смысл |
| --- | --- | --- | --- |
| `unit` | `string?` | конверт | имя линии; отсутствует у безымянной |
| `seq` | `integer` | выводимая | номер звена в линии, монотонно растёт; производная линия начинает отсчёт от места ветвления |
| `derived` | `object?` | выводимая | собранные факты (см. 7.3) |
| `targetCwd` | `string?` | конверт | где должен стартовать преемник; отсутствует ⇒ `= cwd` |
| `externals` | `object?` | конверт | непрозрачные блоки внешних систем (§8) |

Ничего из v1 **не удаляется и не переименовывается**.

### 7.3. `derived`

```jsonc
"derived": {
  "branch": "feature/x",              // git rev-parse --abbrev-ref HEAD
  "commits": ["<sha>", "<sha>"],      // сделанные за сессию, если определимо
  "filesChanged": ["src/a.ts"],       // из git, а не из памяти агента
  "startedAt": "...", "endedAt": "...",
  "checks": [ { "name": "npm test", "ok": true } ]
}
```

Всё содержимое — «лучшее усилие»: не удалось собрать (папка не под git, команда недоступна) —
поле опускается, запись handoff'а **не** падает. Авторское поле `filesChanged` остаётся для того,
что git не видит.

### 7.4. Приёмник версий

`readHandoff` принимает **семейство**: `{v1, v2}` (сейчас — жёсткое `=== "session-link/handoff/v1"`).
Для v1 поля доносятся как есть; `parentHandoffPath` уже абсолютный архив и совместим без правок.

**Обратная совместимость — требование, а не пожелание.** Чтение существующей v1-цепочки обязано
работать без единого вопроса оператору. Именование линии — не «ручное вмешательство» в смысле
починки, а однократный осознанный выбор, и его отсутствие ничего не ломает.

## 8. `externals` — непрозрачный блок

```jsonc
"externals": { "<идентификатор системы>": { /* произвольный JSON */ } }
```

- в json-schema поддерево объявлено неограниченным — любой валидный JSON проходит по построению;
- **session-link не пишет в `externals` сам и не интерпретирует его при чтении** — только сохраняет
  и отдаёт;
- потолок размера блока (рекомендуется 32 КБ). При превышении — **отказ с указанием, какой блок и
  насколько превысил** (ключ системы и размер; что именно внутри — инструмент назвать не может и не
  должен), а не тихая обрезка;
- **fail-soft**: если блок не сериализуется, handoff пишется **без него** с пометкой в логе, а не
  падает целиком;
- в handoff идёт **идентификатор личности, и никогда доступ**. Секретов в handoff'е не бывает.

`seq` (§7.2) лежит **вне** `externals` и ведётся самим инструментом: это данные о собственной
цепочке. Сравнивает `seq` потребитель — session-link решений о свежести не принимает.

## 9. Команды

Существующие: `/session-link [auto|manual] [note]`, `/session-link-go`, `/session-link-write`,
`/session-link-show`.

Добавляются:

| Команда | Что делает |
| --- | --- |
| `/session-link-name <unit>` | называет безымянную линию: переносит слот в `<store>/<unit>/`, заводит запись в оглавлении |
| `/session-link-graph` | печатает `.mmd`/`.dot` в stdout: узлы — handoff'ы, рёбра — `parentHandoffPath`. Рендер картинки вне задачи |
| `--rebuild-index` | пересобирает `index.json` обходом store |

`/session-link-show` дополняется выводом записи из оглавления (состояние линии, `seq`, `head`).

**Тексты отказов** — обязаны называть причину и следующее действие. Примеры формы, не буквальные
строки:

- `unit "Omr Dev" недопустим: разрешено [a-z0-9][a-z0-9-]{0,63}. Возможно, имелось в виду "omr-dev".`
- `линия "omr-dev" уже существует и её голова другая — это ветвление. Подтвердите производную линию "omr-dev-b2" или укажите другое имя.`
- `store занят другим процессом (pid 1234, с 11:20:03). Повторите позже или снимите протухший лок.`
- `блок externals["chat"] — 41 КБ при лимите 32 КБ. Сократите блок; handoff не записан.`

## 10. Инвариант → тест

| # | Инвариант | Проверяется |
| --- | --- | --- |
| 1 | `unit` переживает смену сессии и смену модели | цепочка из 3 звеньев, разные `sessionId` |
| 2 | две линии в одном store не смешиваются | своя ротация, своя цепочка предков |
| 3 | оглавление после handoff названной линии указывает на её `head`; пересборка даёт тот же результат | сравнение `index.json` до и после `--rebuild-index` |
| 4 | обход `parentHandoffPath` возвращает предков **этой** линии, включая звенья в других папках | цепочка через две папки |
| 5 | handoff с `targetCwd` находится из целевой папки; предок в исходной достижим | две папки |
| 6 | отсутствие `externals` не ломает ни запись, ни чтение; незнакомое содержимое сохраняется как есть | round-trip произвольного JSON |
| 7 | v1-файл читается; после записи становится v2 без потери данных | фикстура v1 |
| 8 | развилка не теряет голову; оператор предупреждён | handoff от звена из середины цепочки |
| 9 | session-link не пишет в `externals` сам | сравнение блока до и после записи |
| 10 | параллельная запись не теряет данные | **оба** пути записи + протухший лок |
| 11 | `auto` не остаётся без handoff'а | нет `unit`, нет родителя → безымянная линия |
| 12 | именование не рвёт цепочку | `/session-link-name`, затем обход к предкам |
| 13 | линии одного репозитория видны из разных worktree | `git worktree add`, запись в одном дереве, чтение из другого |
| 14 | legacy-store из старого места найден и перенесён однократно; занятый слот не перезаписан | фикстура по пути `<cwd>/.pi/session_link` |
| 15 | сессия, умершая до авторства, оставляет факты | запись без фазы авторства → `derived` заполнен, документ помечен черновиком |
| 16 | провал сессии не проваливает линию | звено с `blockers` → `state` остаётся `active` |

## 11. Что в контракт НЕ входит

- сеть, протоколы внешних систем, подключение к ним — инструмент только носит блок;
- валидация содержимого `externals`;
- брокер учётных данных — остаётся эскизом до появления per-agent токенов; сейчас достаточно
  идентификатора личности в `externals`;
- хранение архитектурных решений и отвергнутых вариантов: им место в проектной документации, а
  handoff ссылается на них через `filesToRead`. Ссылка лёгкая — ок, тяжёлое содержание — нет;
- уборка архивов (политика хранения N последних либо M дней) — нужна, но отдельной задачей; удалять
  можно только хвост, на который никто не ссылается.
